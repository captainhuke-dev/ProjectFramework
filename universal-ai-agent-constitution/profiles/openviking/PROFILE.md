# OpenViking Context-Substrate Profile for UAAC v4

## Classification

OpenViking is a context substrate, resource index, memory substrate, Skill discovery/storage mechanism, and session continuity aid.

It is not constitutional authority, Project Law, canonical Current Truth, authority registry, verified handoff, checkpoint, job ledger, completion authority, or secret store by default.

## Required mapping

```text
Resource → navigation/reference; canonical only after source identity verification
Memory   → derived continuity context; never authority or Current Truth by storage alone
Skill    → callable aid; must match current Project Procedure/Skill Registry
L0/L1    → discovery/navigation; never complete reading
L2       → detailed candidate; still verify canonical identity
retrieval score → relevance only
session commit  → not checkpoint/handoff/closure
```

## ChatGPT and Codex shared-context flow

```text
Both read Project adoption
→ compare Context Binding
→ compare State Authority Map identity
→ compare Project Continuation Index and applicable lineage-pointer identities
→ retrieve locator through OpenViking
→ fresh-read canonical artifact
→ receiver verifies handoff/artifact
```

## Memory reinforcement control

When recalled context conflicts with canonical state, surface conflict, preserve canonical source, quarantine/supersede stale derived context, and do not recommit it as validated experience.

## Secret boundary

Privacy extraction, placeholders, encryption, or redaction are defense in depth. Secret values remain outside normal memory/resource/Skill ingestion unless a separately authorized secret contract permits it.

## Source review provenance

The v4 design carries forward the reviewed OpenViking profile from the v2.2/v3 line. An adopting Project pins the OpenViking revision it actually validates; this profile does not pin a universal runtime version.
