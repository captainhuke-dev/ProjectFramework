# UAAC v4.2 Deterministic Adoption Runbook

This runbook summarizes the canonical execution order; `INSTALL-UAAC.md` controls installation details

1. Resolve Project authority, root/binding and exact UAAC release identity
2. Create isolated installation workspace; snapshot current base/ref identities
3. Inventory Greenfield/Brownfield/monorepo sources and conflicts
4. Vendor exact UAAC release without modifying it
5. Create/reconcile Project Law and one canonical authority per state class/document role
6. Install Minimal Bootstrap Kernel and exactly one front door per declared Project boundary
7. Materialize Capability Pack, Skills and platform adapters by applicability
8. Create Boot receipt, Project Continuation Index, lineage pointers and visibility policy
9. Configure platform launchers with the shared Kernel/Auto-Boot contract
10. Run schema/static/behavioral/convergence/access/pre-write/visibility tests
11. Recheck base and expected predecessor before commit/push
12. Publish one complete Project tree; remote-read exact identities
13. Record `INSTALLATION_VALIDATED`
14. Obtain separate Project-authority `EFFECTIVE` decision
15. Preserve result/terminal lineage/limitations and exact next action

Stop conditions include Project binding mismatch, unresolved equal-authority document conflict, stale task context, unavailable canonical surface, unverified platform adapter, unknown authority, and failed base/ref freshness
