# CONST-021 — Minimal Project adoption

## Constitutional requirements

- Minimal adoption identifies the Project and boundary, a locally readable pinned local Constitution, and an immutable or verifiable identity for the adopted release.
- Adoption lists only actual routes to Project rules, canonical sources, and continuation that really exist and are used.
- Optional mechanisms are active only through explicitly adopted profiles under applicable Project authority.
- Project rules remain conditional; adoption must not create an empty rules source or placeholder state merely to satisfy structure.
- The effective route must remain usable without a network connection or executable validation step.

## Compliance

Adoption is compliant when its small record resolves the actual Project boundary and local Constitution without fabricated, empty, remote-only, or runtime-state fields.

## Non-prescription

UAAC does not require a standard artifact graph, boot mode, framework installation, receipt, or registry.
