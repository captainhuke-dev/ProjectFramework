# UAAC v4.0 → v4.1 Traceability

## Source decisions

v4.1 incorporates the post-v4.0 design discussion covering installation terminology, one shared Project front door, ChatGPT/Codex convergence, durable continuation for every work state, constitutional Skills, and Project Definition/PRD routing.

## Requirement mapping

| Requirement | v4.1 implementation |
|---|---|
| “ติดตั้งรัฐธรรมนูญ Project” is a shared command | `INSTALL-UAAC.md`, `UAAC-INSTALL-001`, README prompts |
| Install must not mean copy-only | lifecycle and `S-INSTALL-06` |
| All agents start from one place | `governance/UAAC-BOOT.md` template and duplicate detection |
| Front door is not authority/truth | template metadata + validator |
| ChatGPT/Codex use same contract | byte-identical platform shared blocks |
| Local and canonical branch mismatch is visible | governance source policy, `GOVERNANCE_DRIFT`, `S-INSTALL-05` |
| Interrupted work is recoverable | Project Continuation Index + lineage pointers + `S-INSTALL-02` |
| Closed/failed work does not disappear | terminal retention + `S-INSTALL-03` |
| Parallel work does not overwrite | lineage-local pointers + `S-INSTALL-09` |
| Skills are installed by applicability | Project Capability Pack + Procedure Registry |
| Skills do not create authority/truth | CONST-023 and validator |
| PRD/project documents are available | Project Document Registry semantic roles |
| Brownfield documents are not duplicated | inventory/reconcile rule + `S-INSTALL-08` |
| Intended agents can access same state | convergence receipts + `S-INSTALL-10` |
| Project does not depend on mutable upstream | vendoring/pinning + `S-INSTALL-11` |
| Positive install/effective claims need proof | claim contracts and validation receipt |
| README preserves the usage model in Thai | revised `README.md` and Systems Thinking analysis |

## Stable law IDs

No law ID was renumbered or reused. The installation protocol is integrated into existing laws, especially CONST-014, CONST-015, CONST-016, CONST-017, CONST-021, CONST-023, CONST-024, and CONST-025.

## Compatibility

The core remains vendor-neutral. `governance/UAAC-BOOT.md` and local vendoring are the Standard Installation Profile, not universal dependencies; equivalent Project Law profiles may be used if they preserve the same semantics and record variance.
