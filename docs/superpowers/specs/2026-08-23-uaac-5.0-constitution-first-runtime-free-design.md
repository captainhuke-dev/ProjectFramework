## 2. Confirmed defects in UAAC 4.2

The audit confirmed all suspected defect classes:

1. **Mandatory executable installation dependency.** `INSTALL-UAAC.md` requires `python tools/validate_installation.py` before validated installation.
2. **Normative mechanism leakage.** Laws prescribe LLM Wiki, state maps, registries, receipts, continuation indices, lineage epochs, boot modes, capability packs, schema/fixture validation, and publication machinery.
3. **Internal contradiction.** Universal runtime/vendor independence coexists with mandatory framework-like installation and operating artifacts.
4. **Canonical template/schema mismatch.** `constitution-adoption.schema.json` requires `boot_receipt`, `agent_adapter_registry`, and `project_binding`; the canonical adoption template omits them.
5. **Certification blind spot.** The validator checks installed/reference fixtures against schemas but does not schema-validate every canonical template/schema pair before claiming schema and cross-file PASS.
6. **Stale Framework base.** `hz-framework` carries Framework 1.2.2 while current `main` carries 1.2.5 and 38 semantically newer commits.

Independent all-pairs inspection produced 15 PASS and 1 FAIL across 16 v4.2 template/schema pairs. At the same time, the reconciled v4.2 baseline produced:

```text
PACKAGE_VALIDATION_PASS laws=25 scenarios=142
45 passed in 28.81s
```

Those passing legacy checks prove the blind spot rather than disproving it.

## 3. Architectural decision

Release UAAC **5.0.0** as a breaking architectural correction. Preserve stable law IDs `CONST-001` through `CONST-025`, but rewrite mechanism-heavy requirements into universal properties.

Rejected alternatives:

- Patching 4.2 in place would alter published semantics without a major identity change and would leave ambiguous coupling.
- Collapsing all law into one file would discard stable navigation and migration traceability.

Selected model:

```text
CONSTITUTION = LAW
IMPLEMENTATION = OPTIONAL
TOOLING = EXTERNAL TO LAW
MEMORY = ASSISTIVE
CANONICAL PROJECT SOURCE = TRUTH ROUTE
AUTO-BOOT = PERSISTENT INSTRUCTION, NOT PROGRAM
```

## 4. Binding invariants

UAAC core remains usable if all of the following disappear:

```text
Python, pytest, JSON Schema, OpenViking, Serena, MCP, RAG, vector DB,
native Skill runtime, CI/CD, validator CLI, background service,
and the upstream repository host.
```

A capable LLM reading locally pinned Markdown/YAML must still be able to:

- identify and obey applicable UAAC law;
- resolve actual Project rules and canonical Project sources;
- preserve truth, authority, evidence, and instruction boundaries;
- recover materially necessary continuation;
- perform ordinary Project work without user restatement of UAAC, Skill names, or Wiki instructions.

Additional invariants:

- UAAC installation does not install or upgrade ProjectFramework.
- Optional mechanisms never become constitutional authority.
- Profiles activate only by explicit adoption and remain non-normative.
- Project rules are conditional; no empty canonical rules artifact is created.
- A local/offline Constitution copy is the normal operating source.
- No executable command is a condition of constitutional effectiveness.

## 5. Normative ownership

Canonical operational constitutional requirements live only in:

```text
universal-ai-agent-constitution/laws/CONST-001.md
...
universal-ai-agent-constitution/laws/CONST-025.md
```

`UAAC-v5.0-CONSTITUTION.md` contains only identity/version, preamble, hierarchy/precedence, applicability/navigation, and the law index. It cannot contain a second hidden body of operating directives.

`LAW-MANIFEST.yaml` is navigation and inventory metadata. It is not authority, a mandatory reading algorithm, or a completeness receipt.

Guides, templates, profiles, manifests, release metadata, examples, fixtures, conformance tooling, and tests are non-normative.

| `CONST-007` | Preserve instruction authority and input trust; no required adapter or launcher filename. |
| `CONST-008` | Require a bounded set of materially necessary canonical sources and sufficient complete coverage before reliance; search, relevance, and summary may route but cannot establish coverage. |
| `CONST-009` | Require canonical-source recovery before guessing; no mandatory LLM Wiki. |
| `CONST-010` | Preserve risk/authority limits and safe escalation; no state-machine format. |
| `CONST-011` | Remove universal L1/L2/L3 tiers and Capability Pack; retain honest capability and limitation disclosure. |
| `CONST-012` | Preserve decision integrity, countercase, uncertainty, and change conditions; no mandatory procedure shape. |
| `CONST-013` | Preserve semantic fidelity and explicit abridgment; no extension registry. |
| `CONST-014` | Require sufficient durable continuation only when context loss would materially impair safe continuation; no universal index, lineage, or epoch machinery. |
| `CONST-015` | Preserve safe handoff, appropriate receiver verification, and no authority transfer; no mandatory packet or receipt. |
| `CONST-016` | Preserve artifact identity, freshness, synchronization, and conflict handling using source-appropriate identity; no universal hash or precondition format. |
| `CONST-017` | Preserve truthful separation of execution, verification, acceptance, publication, deployment, failure, and closure; no lifecycle engine. |

| `CONST-019` | Preserve proportional reproducibility and reconstruction; no universal ledger. |

## 10. Minimum Project installation

Absolute normal additions:

```text
persistent launcher/instruction update
governance/UAAC.md
governance/UAAC-ADOPTION.yaml
locally readable pinned Constitution content
```

Project-specific rules are conditional. Reuse a real existing source when present; create one only when actual Project-specific rules exist. An empty rules file is an installation defect.

Not universally required:

```text
Bootstrap Kernel, full UAAC-BOOT procedure, Boot Receipt,
State Authority Map, Capability Pack, Adapter Registry,
Skill Registry, Claim Registry, Document Registry, LLM Wiki,
Continuation Index, lineage pointer, epoch,
installation-validation artifact, Python, JSON Schema,
validator, or native Skill support.
```

## 11. Minimal adoption record

The only allowed top-level semantics are:

Angle-bracket values in this illustrative block are deliberate install-time metavariables, not unresolved design placeholders.

```yaml
project:
  id: <stable-project-identifier>
  boundary: <declared-project-boundary>

constitution:
  id: UAAC-001
  version: "5.0.0"
  local_locator: <locally-readable-pinned-constitution>
  immutable_identity: <exact-source-system-appropriate-release-identity>

# Optional only when real.
project_rules:
  - locator: <actual-rule-source>

# Optional only when real.
canonical_sources:
  - role: <project-defined-role>
    locator: <canonical-source>

# Optional only when actually used.
continuation:
  locator: <canonical-continuation-source>

# Optional only when explicitly adopted.
profiles:
  - id: <profile-id>
    locator: <profile-source>
```

Required fields:

- `project.id`
- `project.boundary`
- `constitution.id`
- `constitution.version`
- `constitution.local_locator`
- `constitution.immutable_identity`

Optional unused sections are omitted. Forbidden fields include status/lifecycle, epochs, receipts, claim tokens, boot modes, runtime state, validation results, adapter/capability graphs, registry machinery, and tool configuration.

An optional section cannot be emitted as an empty list or placeholder object merely to satisfy structure.

The normal operational source is the local locator. Remote repository/commit provenance may appear in the vendored release metadata but cannot be the only runtime dependency. Source-appropriate exact identity may be a Git commit, content digest, signed revision, immutable object/version, or equivalent. Runtime hashing on every task is not required.

## 12. Project front door

`governance/UAAC.md` is a short, stable, non-authoritative router.

Allowed responsibilities:

1. Route to adoption.
2. Route through adoption to the locally pinned Constitution.
3. Require bounded selection of materially necessary laws, actual Project rules, and canonical sources.
4. Require sufficient complete coverage of each selected source before reliance.
5. Route to continuation when materially needed.
6. Preserve Auto-Boot and no user restatement.
7. Cite controlling law IDs so law text controls.

Forbidden content:

- duplicate or paraphrased second Constitution;
- current task/status or mutable continuation/state;
- registries, receipts, boot modes, capability/lifecycle graphs;
- Python, CLI, validator, daemon, connector, memory, or Skill requirements;
- ProjectFramework installation;
- remote-only Constitution dependency;
- independent authority or Current Truth claim.

Normal path:

```text
persistent launcher
→ governance/UAAC.md
→ UAAC-ADOPTION.yaml
→ local pinned Constitution
→ bounded materially required Project sources
→ work
```

## 13. Auto-Boot

Preserved user experience:

```text
user does not restate UAAC
user does not name Skills
user does not say "read Wiki"
```

Auto-Boot is persistent instruction behavior. It is not a daemon, boot engine, receipt engine, registry traversal runtime, plugin, or state machine.

## 14. Greenfield installation flow

1. Resolve and inspect the actual Project boundary before assuming it is empty.
2. Preserve discovered files and instructions.
3. Vendor the exact UAAC 5.0 MD/YAML release locally.
4. Create the minimal adoption record.
5. Add only real canonical-source routes.
6. Create Project rules only when actual rules exist.
7. Create the small front door.
8. Reconcile the persistent launcher without overwriting unrelated instructions.
9. Fresh-read launcher → local Constitution → bounded selected sources.
10. Run non-executable constitutional acceptance.
11. Commit/publish only under ordinary Project authority.

The installer does not auto-create ProjectFramework, Wiki, continuation system, Skills, registries, receipts, or validation state.

## 15. Brownfield installation flow

1. Inventory existing rules, requirements, PRD, architecture, current state, handoff, evidence, launchers, and source authority.
2. Preserve canonical homes and unresolved conflicts.
3. Vendor v5 side-by-side.
4. Map real existing rules and sources in minimal adoption.
5. Map continuation only when an appropriate source exists.
6. Add the small front door.
7. Merge the launcher reminder without erasing other instructions.
8. Do not duplicate truth to satisfy templates.
9. Do not install/upgrade ProjectFramework solely because UAAC is adopted.
10. Read back selected routes and run constitutional acceptance.
11. Promote the launcher only after coherence; otherwise preserve prior effective state and report the affected conflict.

## 16. v4.2 → v5 migration

Record the old v4.2 pin, launcher, Project rules/Law, canonical documents/state, continuation/history/evidence, and rollback source.

Then:

1. Vendor v5 beside v4.2.
2. Create v5 front door/adoption without switching the launcher.
3. Map old mechanisms to minimal v5 semantics.
4. Verify the same material Project truth and sufficient continuation.
5. Switch the launcher.
6. Archive/supersede old machinery only after verification and applicable Project authorization.
7. Retain reconstruction history.

Mapping:

| v4.2 mechanism | v5 treatment |
|---|---|
| Binding | Project identity/boundary in adoption |
| Adoption | Minimal v5 adoption |
| Kernel/UAAC-BOOT | Persistent launcher plus small front door |
| Project Law/Document Registry | Direct real rules/source locators |
| State Authority Map | Direct routes or optional high-assurance profile |
| Continuation index/pointers | Actual continuation route or optional assurance |
| Skill/Capability/Adapter registries | Optional reusable-procedures/high-assurance profile |
| Claim Registry/receipts | Historical evidence or optional assurance |
| LLM Wiki/OpenViking | Optional profile |
| Installation Validation | Historical migration evidence, not authority |

## 17. Rollback

Rollback is not universally state-transform-free.

Before v5-only material Project changes, launcher/adoption reversion may be sufficient when state remains v4.2-compatible.

After material work under v5:

1. assess compatibility;
2. identify v5-changed state;
3. verify v4.2 can resolve it;
4. remap incompatible state when needed;
5. preserve evidence/history;
6. then revert launcher/adoption.

No rollback may silently lose state.

## 18. Optional profiles

Profiles remain non-normative and opt-in:

- **high-assurance** may describe state maps, registers, signed revisions, receipts, structured handoffs, schemas/CI, and richer continuation;
- **openviking** may describe retrieval/memory integration while preserving non-authority;
- **projectframework** may map an already chosen ProjectFramework adoption without installing/upgrading it;
- **humanizer** may transform presentation without semantic drift;
- **reusable-procedures** may map native Skills or other callable procedures.

Activation requires explicit listing in adoption and applicable Project authority. Presence on disk does not activate a profile. Profiles cannot create authority or redefine ordinary core compliance.

## 20. Developer-only conformance

External tests verify:

- production distribution extensions are only MD/YAML/YML;
- law IDs are exactly and uniquely `CONST-001` through `CONST-025`;
- no hidden operational law exists in the Constitution entrypoint;
- links, version identity, and release metadata are coherent;
- every declared template/schema pair validates;
- a parameterized negative test corrupts each pair independently and requires failure;
- the adoption schema rejects forbidden runtime/state-machine fields;

- no production/installed operational route depends on `uaac-conformance/`;

## 21. Git integration and tree ownership

The candidate begins from fresh current `origin/main`, then merges `origin/hz-framework` so the result descends from both histories.

Conflict ownership:

```text
managing-project-source/** and current Framework semantics:
  current origin/main 1.2.5 controls

UAAC-specific package/history:
  preserve hz provenance, then refactor to v5

shared/root navigation:
  reconcile semantically by hand
```

Never wholesale choose ours/theirs. Never downgrade Framework. Never mutate or push `main`.

## 22. Publication and remote readback

Before publication:

1. run full constitutional and developer verification;
2. fetch all remotes again;
3. re-observe `origin/main` and `origin/hz-framework`;
4. reconcile semantically relevant main movement;
5. if `hz-framework` moved, stop stale push, integrate it, and rerun affected/full verification;
6. require candidate ancestry from the then-current remote `hz-framework`.

Push only:

```text
HEAD:refs/heads/hz-framework
```

No force push.

Phase A pushes coherent implementation commit(s), fetches/read-backs the remote head, and records the exact implementation remote SHA.

Phase B updates:

```text
docs/uaac-repair/UAAC-CONSTITUTION-FIRST-PATCH-REPORT.md
docs/uaac-repair/UAAC-CONSTITUTION-FIRST-PATCH-STATE.yaml
```

The evidence commit records implementation SHA, remote-readback SHA, verification, migration/rollback status, limitations, and risks. Its self-reference is:

```yaml
evidence_commit_identity: SELF
```

`SELF` resolves to the Git commit containing the exact report/state artifact. A commit cannot literally contain its own SHA. The final operator response reports the literal evidence commit SHA only after final remote publication/readback.

Final readback verifies remote head, ancestry, key files, Framework 1.2.5, UAAC 5.0.0, production extension boundary, and readable audit artifacts.

## 23. Failure handling

For an in-scope failure:

```text
inspect root cause
→ fix
→ add/update regression coverage when useful
→ rerun affected checks
→ rerun full verification before publication
```

Stop only an operation that exceeds authority, cannot be safely reconciled, requires unavailable access with no substitute, or needs destructive/irreversible action outside authorization. Preserve safe work and record the blocker.

## 24. Acceptance criteria

The design succeeds when evidence shows:

- Framework 1.2.5 semantics are preserved;
- UAAC version identity is 5.0.0;
- all 25 law IDs remain stable and receive mechanism-leakage audit;
- operational requirements live only in law files;
- the production boundary contains only MD/YAML/YML;
- no Python/runtime/tool is required for install or operation;
- Auto-Boot remains persistent instruction behavior;
- the minimum Project artifact set remains small and rules remain conditional;
- memory/retrieval/OpenViking/native Skills remain optional and non-authoritative;
- continuation and safe handoff principles survive without a universal state machine;
- UAAC and ProjectFramework installation are explicitly separate;
- all declared schema/template pairs receive positive and independent corruption coverage;
- v4.2 reconstruction, migration, and qualified rollback are documented and safe;
- root navigation distinguishes normative, optional, developer, reference, and historical boundaries;
- implementation and audit-evidence commits are fast-forward-pushed only to `hz-framework` and remotely read back;
- all positive claims match actual evidence.
