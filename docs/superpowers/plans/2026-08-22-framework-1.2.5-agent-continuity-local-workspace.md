# Framework 1.2.5 Agent Continuity, Progressive Verification, and Local Workspace Binding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release Project Source Framework `1.2.5` / Schema `1.0.0` with verified Material Task completion commits, progressive/risk-scoped verification with evidence reuse, environment-scoped Local Workspace Binding for local/MCP execution, and a lightweight Response Close Completeness Gate.

**Architecture:** Preserve the existing `FRAMEWORK-001` root and semantic namespace. Extend Project Location Binding with environment-scoped local workspaces, extend Task/Handoff semantics with verified completion-commit observability, and replace repeated blanket verification with affected-scope/risk-proportional checks plus one full Release Candidate verification and evidence-validity checks at integration. Response-close hardening remains a cheap pre-emit check, not a full release test.

**Tech Stack:** Markdown, YAML, Git/GitHub, Windows/local MCP execution, Python standard library for non-persistent structural verification. No application runtime, validator product, hook, bot, CI/CD, scheduler, background agent, filesystem watcher, or workspace auto-selection is introduced.

**Spec:** `docs/superpowers/specs/2026-08-22-framework-1.2.5-agent-continuity-local-workspace-design.md`

## Global Constraints

- Target Project Source Framework is exactly `1.2.5`; Project Source Schema remains exactly `1.0.0`.
- Existing initialized Projects remain locally pinned and do not auto-upgrade.
- Add no semantic slot, Stable-ID namespace, Project lifecycle state, Git freshness state, or authority family.
- Preserve `ACT DONE ≠ MS REACHED ≠ OUT ACHIEVED`.
- Preserve Framework `1.2.1` Externalized Working Memory / Logical Checkpoint semantics.
- Preserve Framework `1.2.2` Canonical Integration Target, Base Freshness, `STACKED_WORK`, `BASE_STALE`, `REBASE_REQUIRED`, `FORWARD_PORT_REQUIRED`, and `Mergeable ≠ Acceptable`.
- Preserve Framework `1.2.3` Canonical Implementation Source / Development Workspace / Runtime Authority semantics.
- Preserve Framework `1.2.4` Project Location Binding, one-off exact-target semantics, Chat Closure Consistency, and Mandatory Response Close.
- Local Workspace Binding is environment-scoped and reuses exactly `BOUND | NOT_APPLICABLE | VERIFICATION_REQUIRED`.
- Local Workspace Binding `≠` Repository Location Binding `≠` current branch/worktree `≠` Canonical Integration Target `≠` Canonical Implementation Source `≠` Runtime Location.
- MCP `workspaceId`, editor handles, recent-workspace lists, and similar tool identifiers are routing evidence only, never canonical Project identity.
- A Material Git-backed Task may become durably `DONE` only after affected/risk-appropriate verification passes and the required completed state is represented by observed Git commit(s). Read-only/no-repository-mutation Tasks do not require synthetic commits.
- `commit ≠ push`; remote publication remains a separate shared-state/authority action.
- Task-level verification is minimum sufficient affected-scope/risk verification; Logical Checkpoint is not full release verification.
- Full current-distribution verification occurs once on the completed Release Candidate, then may be reused while its bound candidate/dependency/target assumptions remain valid.
- Integration checks invalidate/re-run only affected verification unless impact cannot be bounded safely.
- Response Close Completeness Gate runs before every Framework-governed assistant response and verifies the assistant response representation only; it must not claim visibility into downstream app rendering.
- ChatGPT/Claude shared launcher marker bodies remain byte-identical and each complete launcher remains `<= 4,500` Unicode characters.
- Historical amendments/specs remain historical; create a new Framework `1.2.5` amendment rather than editing prior amendments.
- No executable enforcement tooling is authorized by this plan.
