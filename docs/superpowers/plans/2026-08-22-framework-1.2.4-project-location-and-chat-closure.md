# Framework 1.2.4 Project Location Binding and Chat Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release Project Source Framework `1.2.4` with durable Project Location Binding for GitHub/Google Drive, fail-closed connector routing, deterministic Chat Closure Consistency, and the approved bracketed Mandatory Response Close format.

**Architecture:** Keep active local `FRAMEWORK-001` as the single canonical governance home for Project working-location binding. Propagate the approved semantics through Core Governance, skill, root/starter templates, handoff guidance, launchers, pressure scenarios, and release metadata without creating a new branch authority, Stable-ID family, schema namespace, or connector automation. Verify the release with semantic pressure scenarios, current-version scans, launcher byte-parity/Unicode-length checks, and Framework `1.2.2` Base Freshness gates.

**Tech Stack:** Markdown, YAML, Git/GitHub, shell commands, Python standard library for non-persistent verification checks.

**Spec:** `docs/superpowers/specs/2026-08-22-framework-1.2.4-project-location-and-chat-closure-design.md`

## Global Constraints

- Target Project Source Framework: `1.2.4`.
- Project Source Schema remains exactly `1.0.0`.
- Add no semantic slot and no Stable-ID namespace.
- Active local `FRAMEWORK-001` is the canonical home of Project Location Binding.
- Project Location Binding is a routing/work-boundary contract, not Canonical Implementation Source.
- Repository Location Binding `≠` current work branch/worktree `≠` Canonical Integration Target `≠` Canonical Implementation Source.
- Do not add `canonical_branch` or any competing Git branch authority; preserve Framework `1.2.2` Canonical Integration Target/Base Freshness semantics.
- Binding states are exactly `BOUND | NOT_APPLICABLE | VERIFICATION_REQUIRED`.
- `VERIFICATION_REQUIRED` is fail-closed for Material mutation; read/search/discovery may continue to resolve candidates.
- `NOT_APPLICABLE` blocks Material Project work through that connector until an explicitly approved Root Governance binding/scope change.
- `BOUND` requires durable routing identity: GitHub owner/repository or canonical repository URL; Drive folder ID or canonical folder URL.
- A one-off User Explicit Instruction naming an exact target may authorize only that specific action when otherwise allowed; it does not persistently rewrite Project Location Binding.
- Changing active Project Location Binding is a `FRAMEWORK-001` Root Governance mutation requiring User Explicit Approval plus revision/validate/promote/supersede/archive flow.
- Connector discovery, search ranking, and recent activity never transfer Project authority by themselves.
- `ไม่มีขั้นตอนถัดไป` requires `START_NEW_CHAT`.
- `CONTINUE_CURRENT_CHAT` requires one concrete Next Action.
- `PERSISTENCE_PENDING` requires `CONTINUE_CURRENT_CHAT` plus a concrete persistence/recovery Next Action.
- `START_NEW_CHAT` may still carry a concrete Next Action when continuation is durable and fresh-chat safe.
- Mandatory Response Close fields render as `[Next Action]:`, `[Chat]:`, `[Reason]:`, `[Required Read]:`, each in its own Markdown paragraph.
- Canonical lifecycle tokens remain unescaped `CONTINUE_CURRENT_CHAT` and `START_NEW_CHAT`; Markdown escaping is presentation-only.
- ChatGPT/Claude shared launcher text between markers remains byte-identical.
- Each complete ChatGPT/Claude launcher remains `<=4,500` Unicode characters.
- Existing initialized Projects do not auto-upgrade.
- Historical specs/amendments remain historical and are not rewritten.
- This implementation is governance/documentation only: do not add application code, connector synchronization, validators, schedulers, bots, CI/CD, hooks, or background automation.
