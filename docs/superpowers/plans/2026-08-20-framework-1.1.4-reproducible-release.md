# Framework 1.1.4 Reproducible Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release Project Source Framework `1.1.4` with a machine-readable release descriptor, immutable-tag bootstrap policy, and exact Project-local Git provenance recording while keeping Project Source Schema `1.0.0`.

**Architecture:** `main` remains the discovery entrypoint for NEW Projects, but `FRAMEWORK-RELEASE.yaml` declares the stable immutable bootstrap tag. A consuming Project resolves that tag, records the observed commit SHA in its local `00` provenance block and Manifest metadata, then treats the pinned local Project Source as authoritative. The release descriptor never embeds the SHA of its own containing commit, avoiding self-reference.

**Tech Stack:** Markdown/YAML governance artifacts, Git/GitHub branch + pull-request workflow, shell/Python structural validation; no Phase-B validator package or GitHub Actions workflow in this release.

**Spec:** `docs/superpowers/specs/2026-08-20-release-integrity-and-certification-roadmap-design.md`

## Global Constraints

- Repository: `captainhuke-dev/ProjectFramework`.
- Phase A Framework version becomes exactly `1.1.4`; Project Source Schema remains exactly `1.0.0`.
- Stable release tag name is exactly `v1.1.4`.
- `FRAMEWORK-RELEASE.yaml` MUST NOT contain a binding `commit_sha` for its own release commit.
- NEW Project exact provenance is `framework version + release tag + resolved Git commit SHA recorded locally`.
- Existing Projects MUST NOT fabricate historical SHA provenance or auto-upgrade.
- Platform Project instructions remain launchers and MUST NOT override an active local `FRAMEWORK-001`.
- Historical Framework amendment files remain immutable; add a new `framework-governance-amendment-260820-0821.md`.
- Phase A does not add the `tools/framework_integrity/` validator, `.github/workflows/framework-integrity.yml`, Golden Reference Project, or fresh-agent certification claims; those belong to later phases.
- Git tag creation and branch-protection mutation are external gates because the available GitHub connector exposes read/verification but no tag/protection mutation action.
- Do not claim `v1.1.4` exists or `main` is protected until fresh verification observes those states.
