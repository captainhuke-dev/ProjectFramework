# UAAC 5.0 Constitutional Acceptance

Status: **HUMAN/LLM-READABLE — NO EXECUTABLE PREREQUISITE**

These scenarios test constitutional usability by direct reading and reasoning. They are developer assurance, not constitutional authority.

## CA-01 — Offline local Constitution

**Given:** An adopted Project has its persistent launcher, router, adoption record, and complete pinned UAAC Markdown/YAML release locally available while the network and upstream repository are unavailable.

**When:** An Agent begins material work.

**Then:** The Agent resolves the local entrypoint and applicable law files without remote access and does not treat the outage as loss of constitutional effectiveness.

**Required reading:** Launcher, `governance/UAAC.md`, adoption, local Constitution entrypoint, and selected laws.

**No executable prerequisite:** Direct source readback is sufficient.

## CA-02 — Ordinary-task Auto-Boot

**Given:** The persistent launcher routes material work to `governance/UAAC.md`.

**When:** The user asks only “Fix this bug” and does not mention UAAC, a Skill, or a Wiki.

**Then:** The Agent follows the local UAAC route, considers any available relevant procedure, and resolves Project sources before acting.

**Required reading:** Launcher, Project router, adoption, and `CONST-007`, `CONST-021`, `CONST-023`.

**No executable prerequisite:** Persistent instruction behavior is inspected directly.

## CA-03 — Bounded sufficient complete coverage

**Given:** Several Project sources are related to a task but only a bounded subset materially controls the decision.

**When:** Search or a summary identifies candidate sources.

**Then:** The Agent selects the materially required bounded set, obtains sufficient complete coverage of every selected source, and does not claim that search or summary alone proved coverage.

**Required reading:** `CONST-008` and the selected Project sources.

**No executable prerequisite:** The source-selection and coverage reasoning is reviewed directly.

## CA-04 — Canonical source defeats memory

**Given:** Agent memory conflicts with a readable canonical Project source.

**When:** The conflict becomes material to work.

**Then:** The canonical source controls, the conflict is surfaced, and memory is not represented as Current Truth.

**Required reading:** `CONST-005`, `CONST-009`, and the conflicting canonical source.

**No executable prerequisite:** The authority/freshness comparison is readable evidence.

## CA-05 — Conformance deletion independence

**Given:** The entire developer conformance sibling and all optional tools are absent.

**When:** A capable LLM opens an installed Project.

**Then:** Launcher → router → adoption → local Constitution → selected Project sources remains complete and usable.

**Required reading:** Installed Project Markdown/YAML only.

**No executable prerequisite:** The route is checked without developer tooling.

## CA-06 — Greenfield omits empty artifacts

**Given:** A Greenfield Project has no Project-specific rules and no materially needed continuation source.

**When:** UAAC 5.0 is installed.

**Then:** Adoption contains only required Project/Constitution fields and no empty rules, continuation, registry, receipt, or state artifact is created.

**Required reading:** Greenfield fixture, `CONST-021`, installer, and adoption template.

**No executable prerequisite:** The small file set and YAML fields are inspected directly.

## CA-07 — Brownfield reuses canonical homes

**Given:** A Brownfield Project already has real rules, PRD, and current-state sources.

**When:** UAAC 5.0 is installed.

**Then:** Adoption points to those sources without duplicating their truth, and unrelated launcher instructions remain intact.

**Required reading:** Brownfield fixture, installer, and `CONST-005`, `CONST-021`.

**No executable prerequisite:** Direct locator-to-source readback is sufficient.

## CA-08 — Material continuation recovery

**Given:** Context loss would materially impair safe continuation and the Project has a durable continuation route.

**When:** A successor Agent resumes work.

**Then:** The successor recovers objective, state, constraints, evidence, risk, and next action sufficiently without inventing facts or inheriting authority.

**Required reading:** Adoption continuation locator, continuation source, `CONST-014`, and `CONST-015`.

**No executable prerequisite:** A receiver can assess sufficiency from the durable sources.

## CA-09 — ProjectFramework separation

**Given:** A Project asks to install UAAC and has not separately adopted ProjectFramework.

**When:** The installer resolves the requested product.

**Then:** It installs no ProjectFramework files, changes no Framework version, and leaves the optional mapping profile inactive.

**Required reading:** Installer, adoption, `CONST-020`, and the optional ProjectFramework profile.

**No executable prerequisite:** Product boundaries and installed files are directly inspectable.

## CA-10 — Safe v4.2 migration and rollback

**Given:** A Project has an immutable 4.2 pin, material truth routes, continuation, and a preserved rollback source.

**When:** It builds the 5.0 route side-by-side and later considers rollback after 5.0 work.

**Then:** The launcher switches only after coherence, old history remains reconstructible, and rollback assesses compatibility/remaps changed state before reversion.

**Required reading:** Migration fixture, migration guide, `CONST-022`, and rollback notes.

**No executable prerequisite:** The two routes and compatibility conditions are reviewed from durable documents.

## CA-11 — Sole operational law boundary

**Given:** Guides, profiles, release metadata, examples, and developer tooling express helpful procedures or mappings.

**When:** A conflict over an operational constitutional requirement arises.

**Then:** The applicable `laws/CONST-*.md` file controls; no guide, profile, manifest, or tool creates a competing law body.

**Required reading:** Constitution entrypoint, selected law file, and the conflicting non-normative material.

**No executable prerequisite:** Normative classification and precedence are readable in the distribution.
